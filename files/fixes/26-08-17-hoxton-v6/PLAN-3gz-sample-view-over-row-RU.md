## Заявка «2 места вливают ответ сервера поверх значений строки» — подтверждена; механизм шире

**Два места слияния — те же:**
- страница почвы: `_snFetchAndRender` (`soil-nutrition-analysis.js`, около `:1757-1770`) — `GAIP_DASHBOARD_DATA.computed.soilNutrition = Object.assign({}, existing, snData)`;
- водный баланс: `_wbSwitchSample('soil', …)` (`water-balance-analysis.js`, около `:1428-1441`) — то же выражение.

`snData` — ответ `/api/samples/{id}/analyse` для **выбранной** пробы: нутриенты, вердикт, `pH`, `ECe`, `soilNa`, `CEC`, метка и дата пробы. Всё прочее в `soilNutrition` — годовая потребность, ткань, зоны, методология — остаётся от **пробы строки анализа**. После слияния один объект описывает две пробы, и ничто на экране этого не говорит.

**Это происходит без действия человека.** Обе страницы помнят последнюю выбранную пробу в `localStorage` (`soil-nutrition-analysis.js`, около `:1706`, `:1743-1751`; `water-balance-analysis.js` — ключ `gilba_wb_active_soil`, около `:18-21`). При загрузке, **если запомненная проба не та, что в строке, страница сама делает слияние**: почва — около `:1857-1858`, водный баланс — около `:1537-1541`. Человек открывает страницу — и видит нутриенты пробы, выбранной неделю назад, рядом с годовой потребностью и водным балансом, посчитанными по другой.

**Кто читает смешанный объект:**
- страница почвы, `render()` (около `:1486`) — карточки нутриентов, вердикт — выбранная проба; годовая потребность, ткань — проба строки;
- водный баланс, `renderSoilWaterInteraction(sn, wb)` (около `:1579`, `:1590`) — почвенная часть от выбранной пробы, `wb` — водный баланс строки, посчитанный с пробой строки.

**Где это возможно на стенде — площадки с двумя и больше живыми почвенными пробами:** `Burns` 26, `New test - location` 13, `Russley` 3, `Hoxton` 2. Сколько браузеров помнят другую пробу, со стенда не узнать.

## Корневая причина

Выбор пробы для просмотра — это состояние страницы. Страница хранит его в глобале данных строки (`GAIP_DASHBOARD_DATA`), а не в своей переменной, и возобновляет из `localStorage`. Класс `GH-459`: печатается состояние страницы под видом данных объекта.

## Устройство

1. **Глобал строки не меняется.** `GAIP_DASHBOARD_DATA.computed.soilNutrition` остаётся ответом строки анализа; оба `Object.assign` уходят. (2)
2. **Просмотр другой пробы — своя переменная страницы** (`viewedSample`: проба и её ответ `/analyse`). Карточки, которые описывают одну пробу (нутриенты, вердикт, `pH`, `CEC`, `ECe`, `Na`), рисуются из неё, если она выбрана, иначе — из строки. (2 — по одному на страницу)
3. **Разделы, посчитанные прогоном по пробе строки** — годовая потребность на странице почвы, взаимодействие почвы и воды на водном балансе, — **при выбранной другой пробе не рисуются из смеси.** Что вместо них — вопрос владельцу (ниже). До её ответа: раздел остаётся по пробе строки, и у раздела подпись, по какой он пробе. Метка и дата пробы строки в ней уже есть (`sampleLabel`, `sampleDate`).
4. **Запомненный выбор при загрузке** — удобство одного браузера, правило его разрешает (`CLAUDE.md`: «`localStorage` для удобств одного зрителя»). Но он не должен **молча** открывать другую пробу: при восстановлении выбора страница показывает, что смотрит не пробу анализа. Как — тот же вопрос владельцу. (0 — входит в п. 2–3)

## Вопрос владельцу — записать в пункт

**Что показывать, когда человек смотрит на странице почвы или водного баланса не ту пробу, по которой посчитан последний анализ.** Сегодня страница молча смешивает: нутриенты — выбранной пробы, годовая потребность и водный баланс — пробы анализа. После правки смеси не будет, но нужно её правило:
- (а) разделы анализа (годовая потребность, почва и вода) остаются по пробе анализа, с подписью «по пробе X от даты Y»;
- (б) при выбранной другой пробе эти разделы скрываются с фразой «посчитано для пробы X — нажмите Re-run, чтобы посчитать для выбранной»;
- (в) выбор пробы на этих страницах убирается: страница показывает пробу анализа, а другая проба выбирается для Re-run.

Я бы выбрала (а): человек видит и выбранную пробу, и то, к какой пробе относятся расчётные разделы, без новых действий. Решать ей: это то, что человек видит на странице анализа. Касается обычного экрана — площадки с несколькими пробами, у клиентов это обычное дело. **Днём, не ночью** — по правилу координатора идёт к ней.

## Браузерные копии в этой области

- **`localStorage` с выбором пробы** — два ключа (страница почвы, `gilba_wb_active_soil`). Остаются как удобство, но перестают молча подменять данные страницы (п. 4).
- **`GAIP_DASHBOARD_DATA`** — ответ сервера, отрисованный в страницу, не копия. Правка перестаёт его переписывать.
- **`global._gilbaActiveWaterSample`** (водный баланс, около `:1420`, `:1466`) — выбор водной пробы для Re-run, параметр прогона (`GH-586`), не данные экрана. Не трогается.

Искала `localStorage`, `sessionStorage`, `GAIP_DASHBOARD_DATA`, `Object.assign` в обоих файлах.

## Признак сдачи — числом

- Мест, переписывающих `GAIP_DASHBOARD_DATA.computed.soilNutrition` на странице: 2 → 0.
- Разделов, рисуемых из смеси двух проб: 2 (годовая потребность, почва и вода) → 0.
- **Тесты (jsdom):** строка с пробой A, выбрана проба B — нутриенты B, годовая потребность A с подписью A; глобал после выбора равен глобалу до выбора — сравнение с фикстурой строки, а не с собой; то же при восстановлении выбора из `localStorage` при загрузке. Мутацию выбирает ревьюер.
