## Устройство

**Единственный владелец соответствия «узел ↔ имя модуля» — узел графа, поле `module`.** Значение снимается с нынешних вызовов, не придумывается.

**Кто получает его от графа:**
1. **Обход прохода** регистрирует узел под `node.module`, записывает `notApplicable` и сбор — под ним же. Второго способа назвать модуль в JS нет.
2. **Сервер.** `stepWriting` возвращает `module` узла, который пишет ключ. Граф он уже читает, `stepsFromGraph` меняется так: вместо `ключ → id узла` строит `ключ → module узла`. `stepCandidates` и перебор по `STEP_NAMES` удаляются.
   - Путь через `assembledFrom` для ключей, которые собирает слой записи, остаётся: это другое объявление, и оно уже в `analysis-result.schema.json`.
3. **Слой записи** (`mlsn`, `water`) и **сбор каскада** пишут под `module` своих узлов. Сбор каскада — срез 3 вместе с тканью; в срез 2 не входит.

**Почему не выводить имя в JS тем же правилом.** Правило уже ошибается на `disease-forecast`, и ошибается молча. Перенос его в JS дал бы два выводящих — «два читателя со сторожем». Объявление — один читатель.

**`STEP_NAMES` после этого — только слова для людей, `module → слово`, и перестаёт быть словарём-фильтром.** Слова в нём — копия `label` графа, её держит сторож `gh572`: то самое «для своего случая верно, образцом не является». Перенести слова в граф рядом с `module` значит убрать и эту копию. Это отдельное предложение, 24 ключа, в срез 2 не включаю.
