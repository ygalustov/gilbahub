# План 3вм (`GH-768`): серверная оценка микроэлементов AA совпадает с прогоном

Аналитик — Аня, 25.09.2026 12:00. План идёт владельцу до разработки: её решение 09:46. Всё ниже снято чтением кода и запросами к базе стенда только на чтение. Тесты не запускались, стенд не тронут.

## Цель

Когда человек на странице почвы выбирает пробу, оценку показывает сервер. Для площадки с методологией Ammonium Acetate (AA) эта оценка должна совпадать с той, что даёт прогон, по всем десяти элементам.

Расчёт в браузере не трогаем: решение владельца 22.09, сейчас переносятся только хранение и чтение. Меняется одна серверная оценка.

## Что сейчас

  - Литерал `aaRanges` задаёт диапазон всем десяти элементам. У микроэлементов: Fe 40–100, Mn 10–50, Cu 0.5–3, Zn 1–5, B 0.4–1.5, одинаково для песков и прочих.
  - Сертификатом лаборатории перекрываются только P, K, Ca, Mg, S (`["P", "K", "Ca", "Mg", "S"].forEach`, около `:3264`).

Других вызывающих у `computeNutrients` нет, маршрут один (`routes/web.php:137`). Это установлено чтением, экраном не проверено (см. «Как проверить»).

  - Площадок с методологией AA — 4: Test5 - NZ, Russley, Test - GC - NZ - delivery, Test - GC - NZ - warm season grass test.

## Корневая причина

Серверная таблица AA — вторая копия литерала движка, и скопирована она не целиком: пять строк из десяти. Для тех пяти, которых нет, сервер молча берёт другую методологию. Класс — «чужая методология»: тот же, что был закрыт для SLAN в `GH-752`, часть C.

## Что меняется на экране, два исхода

- **Делаем.** На странице почвы при выборе пробы у 4 площадок AA 15 значений микроэлементов показывают диапазон прогона и его слова: Low / Sufficient / High. У трёх значений меняется и класс: B 0.3 становится Low, Fe 168 и Zn 5.7 — High. Пока проба не выбрана, страница и сейчас показывает то же, что прогон, и это не меняется. Числа в сохранённой строке не меняются: её пишет прогон.
- **Не делаем.** До выбора пробы и после одно и то же число оценивается по-разному. У трёх значений расходится и вывод: например, Fe 168 до выбора — «выше диапазона», после — «достаточно».

## Устройство

1. **Один файл диапазонов AA, читает его сервер** — по принятому образцу `GH-752`, часть B (сдача 4 принята Веней 25.09 в 07:39).
   - Новый `assets/aa-ranges.json`: по два типа почвы (`sands`, `others`), все десять элементов, числа переносятся из литерала движка без правки.
   - Класс `App\Support\AaRanges` по образцу `App\Support\SlanRanges`.
   - `AA_RANGES` в контроллере уходит, ветка AA берёт диапазон из `AaRanges` для всех десяти элементов.
2. **Сертификат перекрывает только P, K, Ca, Mg, S — списком, как в движке**, а не «всё, на что `getRangesPpm` что-то вернул».
   - Сегодня это ничего не меняет: в `resources/data/hill-labs-sample-types.json` порогов для микроэлементов нет.
   - Зато расхождение не откроется само, если в данных сертификата появится Fe.
3. **Подпись порога.**
   - Для диапазона по текстуре сервер пишет целые числа («75-175»), прогон — с одним знаком («75.0-175.0»). Это есть и у пяти элементов сегодня, в числах не расходится, этим планом не меняется.
   - Для новых пяти сервер печатает так же, как для первых пяти.
4. **Сторож — по поведению, и он уже есть.**
   - Сетка «сервер оценивает так же, как прогон» из `GH-752`: `tests/gh752-the-server-grades-a-sample-as-the-engine-does.test.js` строит оценки прогона, `app/tests/Unit/Gh752TheServerGradesASampleAsTheEngineDoesTest.php` сравнивает с ними сервер.
   - В ней уже стоят клетки AA, но микроэлементы AA вынесены исключением: печатаются и не утверждаются (около `:77–81`, «printed, not asserted, until it is decided»). Это исключение снимается — после правки оно должно утверждаться.
   - Вход сетки сегодня один, и на нём оценки совпадают случайно: Fe 70, Mn 40, Zn 4, Cu 1 внутри обоих порогов, B 0.2 ниже обоих. Добавляется второй вход, который разводит пороги: значение выше верхней границы (как Fe 168) и значение между порогом MLSN и нижней границей AA (как B 0.3).
5. **Страховка переноса чисел.** JS-тест «файл несёт то, что несёт литерал движка», по образцу `tests/gh752-the-slan-ranges-have-one-file.test.js`: оба типа почвы, все десять элементов.

## Основание устройства, названное вслух

- **Копий будет две: литерал в движке и файл, который читает сервер.** Движок файл не читает, пока расчёт в браузере не трогаем. Так же сегодня устроен SLAN: `slan-ranges.json` читает только сервер, литерал остался, а переключение движка на файл (часть E `GH-752`) не начато и отложено вместе с SLAN. `CLAUDE.md` прямо называет это «дублированием с ремнём безопасности», а не исполнением правила «один файл — один читатель». Ремнём здесь служат два сторожа: сетка поведения (пункт 4) и сверка чисел (пункт 5). Вторая копия уйдёт, только когда владелец разрешит трогать движок. Тогда AA и SLAN переключаются одним приёмом.
- **Прогон — эталон.** Это правило проекта: алгоритмы совпадают со старым хабом, а `mlsnEngine` — его расчёт. План НЕ проверяет, верны ли сами числа Fe 40–100 и остальные: цель владельца — совпадение с прогоном. Если числа в движке неверны, после правки они будут неверны в двух местах одинаково. Это отдельный вопрос, в этот план он не входит.
- **Почему файл, а не пять строк в `AA_RANGES`.** Пять строк в константе дают ту же защиту: сетка поведения ловит расхождение в обоих вариантах. Файл дороже на два места (JSON и класс). Выбираю файл: AA и SLAN тогда устроены одинаково, и будущее переключение движка — один приём, а не два. Решение архитектурное, моё. Если нужен самый дешёвый вариант — пять строк в `AA_RANGES`, и больше ничего в плане не меняется.
- **Посылка «оценку сервера видит человек после выбора пробы» установлена чтением кода.** Живым экраном она проверяется в окне, см. ниже.

## Подводные камни

- **Порядок веток в `computeNutrients`:** «нет методологии» → SLAN → AA → MLSN. Ветка AA не должна перехватить площадку SLAN или MLSN. Сетка несёт клетки всех трёх методологий, это проверяется ею.
- **`sands` / `others`** выбирается тем же `$texKey`, что и сегодня. У микроэлементов значения одинаковы для обоих типов, у K и Mg — нет. Числа брать из литерала движка, не из памяти.
- **Граница включительно.** Верхняя граница у прогона `<=` (`GH-276`). У сервера сегодня так же, не сломать.
- **Не трогать `ClassificationConstants::MLSN_THRESHOLDS`.** Их читает ветка MLSN, а MLSN владелец велела не трогать (25.09 09:01).
- **`tests/gh305-aa-generic-range-ceiling.test.js`** уже знает про `AA_RANGES` контроллера: его ссылки на константу надо перевести на файл, а не удалить.
- **Кириллицы в коде нет, ссылок на номера вопросов нет** — только `GH-768`.
