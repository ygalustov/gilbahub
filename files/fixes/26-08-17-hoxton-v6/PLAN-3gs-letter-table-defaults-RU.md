# План 3гс (`GH-NNN` — от координатора): умолчания таблицы букв — снять, и в той же работе защитить отрисовку `/hub`

Аня, 01.10.2026, ночь. Сняты чтением, `SELECT` (только чтение) и разбором `gaip_render_results` через `@babel/parser` + `@babel/traverse` — скрипт в скрэтчпаде, `render-null-reads.js`, только читает. Прогонов не было.

`md5`: `hub-tissue-v3.js` `c41c2855…`, `hub-persistence.js` `51f0a247…`, `dashboard-ui.js` `ab1c3172…`, `word-export.js` `c7a52a03…`. Вход — `LETTER-TABLE-defaults-intake.md` (скрэтчпад аналитика): семь умолчаний, частота, достижимость.

## Первое: снять подстановку без защиты отрисовки — значит уронить прогон целиком

**Что держит подстановка.** Отрисовка `/hub` получает результаты каскада буквами по позиции (`gaip_render_results(e, t, r, n, i, a, o, s, l, d)`) и разворачивает пять из них без проверки на `null`. Замер — разбор по привязкам параметров, внутренние функции с теми же буквами отделены:

| параметр | результат | обращений без проверки (`x.y`, не `x?.y`) |
|---|---|---|
| `i` | трафик (`oe`) | 30 |
| `a` | упругость (`ne`) | 26 (ещё 3 через `?.`) |
| `o` | азот (`ae`) | 18 |
| `s` | turf manager (`me`) | 8 |
| `l` | тень (`se`) | 125 |
| `r`, `n` | MLSN, вода | 0 — в функции не разворачиваются |
| `d` | износ (`le`, всегда `null` с `GH-787`) | 5, **все под `if (d && …)`** — это и есть образец |

Примеры первых обращений — якоря:
- трафик — `i.TrafficRisk > 10 ?`;
- упругость — `var oe = void 0 !== a.FI ? (100 * a.FI).toFixed(0) : "-",`;
- азот — `var z = o.status || "Unknown",`;
- turf manager — `` `<p><strong>Playability:</strong> ${s.playability}</p>` ``;
- тень — `xe = l.c3Opt > 0 ? l.c3Opt.toFixed(1) : "N/A",`.

**`i.TrafficRisk` не единственный: мест пять — по одному на результат. Обращений 207.** Сколько из них исполняется без проверки выше по коду, построчно не разбирала. Поэтому доказательство защиты — поведение (раздел «Проверка»), а не счёт.

**Что будет при падении — не молча, но прогон целиком.**
- Вызов стоит в первом прогоне после каскада (`hub-tissue-v3.js`, якорь `gaip_render_results(t, a, l, d, oe, ne, ae, me, se, le);`). **До** публикации `GAIP_STATE` и до события `gaip:analysis-complete`.
- Исключение ловит `catch` того же блока и шлёт `gaip:analysis-complete` с `{ error: true, message }` (`GH-547`, якорь `// GH-547 (stage 2): the message travels with`).
- Прогонщик ставит провал `_fail('calculation-error', …)` (`hub-persistence.js`, якорь `if (d.error) {`) и сообщает его серверу.
- Открыватель снимает кнопку с ожидания и печатает человеку «The re-run did not complete: {reason}. Try Re-run again.», а прежний результат оставляет (`dashboard-ui.js`, `stall`).

**Что увидит человек:** Re-run на площадке без результата трафика (или упругости, азота, тени) не пройдёт ни разу. На экране — сообщение о несостоявшемся повторе с причиной «calculation-error», числа прежние.
- Прогон падает целиком, а не только полив: весь проход, запись строки, все модули.
- Сегодня так было бы у **3 из 13** площадок — по последним строкам у них нет `nitrogen`, `traffic`, `firmness`.
- **В объединённом экспорте хуже:** `waitForAnalysis` дождётся события с ошибкой так же, как успеха, и `collectData` возьмёт глобалы предыдущей площадки. Это класс `GH-459`.

**Отсюда: чинить до 3гл не нужно, но защита и снятие — одной сдачей.** Сегодня отрисовка не падает: умолчания её держат. Падение появится ровно в правке, которая снимет умолчания, если защиты нет. С 3гл не связано: при падении теряется весь прогон, и то, где считается полив, этого не меняет.

## Сверка с 3гл и его восемью читателями, 01.10 — предмет не меняется, порядок не нужен

- **Полива нет в таблице букв.** Его нет ни среди семи умолчаний, ни среди пяти параметров отрисовки без защиты. Восемь читателей глобала полива (перечень в плане 3гл) читают `GAIP_IRRIGATION_RESULT` и `GAIP_IrrigationResults`, не буквы. Пересечений по предмету нет.
- **Общее место — одна функция, `gaip_render_results`, но разные блоки.** 3гс ставит проверки в пяти разделах: трафик, упругость, азот, turf manager, тень. 3гл меняет блок полива (якорь `var Ut = document.querySelector(".gaip-irrigation-body");`): вместо вызова планировщика — готовый результат прохода.
- **Шестой защиты для полива не нужно, ни здесь, ни в 3гл.** Блок полива переживает `null` уже сегодня. Условие `Bt && !Bt.error` уводит в ветку `Ut.innerHTML = '<p class="gaip-note">' + (Bt?.error || "Irrigation calculation unavailable") + "</p>"`, и блок стоит в своём `try … catch`. После 3гл результат прохода `null` даст ту же надпись. 3гл обязан сохранить это условие, а не развернуть `Bt` без проверки — строка в подводные камни 3гл.
- **Довод «падение отрисовки теряет полив» после 3гл (а) снимается, «теряет весь прогон» — остаётся.** Полив уйдёт в проход, но исключение из раздела трафика по-прежнему обрывает весь `try` прогона до публикации и события.
- **Порядок.** В очереди 3гс идёт после 3гл, и так удобнее: правки в одной функции не наложатся. Но необходимости нет: блоки разные, и каждая работа доказывает себя своими случаями.

## Корневая причина

Таблица букв подставляет объект-заглушку, когда каскад результата не дал. Заглушка делает две вещи сразу. Держит отрисовку от падения — это нужно. И выдаёт себя за результат для всех, кто читает глобал: нули трафика, `opt: 200`, «Not computed» как объект, который проходит проверку «результат есть» — это ложь. Обе роли держит одно выражение. Поэтому снять ложь, не сняв опору, нельзя.

## Устройство

**Развести две роли: публикация получает `null`, отрисовка — отдельный ответ «не посчитано».**

1. **Таблица букв — без умолчаний.** В `gaip_extractCascadeResults` семь выражений `computed.X || { … }` → `computed.X ?? null`. Для `d` — `computed.water ?? computed.waterBlend ?? null`. (1)
2. **Отрисовка — одна проверка на раздел, по образцу `d`.** Пять разделов: трафик, упругость, азот, turf manager, тень.
   - `null` — раздел печатает «не посчитано в этом анализе» (слова — ниже) и свой блок не строит.
   - Проверка стоит **в начале блока раздела**, а не у каждого из 207 обращений.
   - Трафик и упругость строятся одним блоком карточки (`var oe = … a.FI`, `le = … i.TrafficRisk`) — проверка раздельная, каждая своё. (5)
3. **Второй вызов — повтор прохода** (`gaip_republishCascadePass`, якорь `gaip_render_results(pass.state, pass.weather, x.l, x.d, x.oe, …)`) — уже в `try/catch` с предупреждением. Защита п. 2 закрывает и его, отдельной правки нет. (0)
4. **Word — правки нет. Поправка 01.10, моя ошибка во входном файле и в первой редакции плана:** заглушки до печати Word не доходят ни в одном из трёх мест. Проверено чтением условий печати:
   - **тень:** раздел печатается только под `if (data.shade && data.shade.currentDLI) {` (`word-export.js`, около `:14073`), пункт оглавления — под тем же условием (`contentItems.push('• Light & Shade Analysis')`). У заглушки `currentDLI` нет, поэтому раздела нет вовсе. Цели `|| 18`, `|| 12`, `|| 30`, `|| 24` записываются в `data.shade`, но не печатаются: остальные их читатели требуют `currentDLI` или `deficit`, а `deficit` считается только при `currentDLI && targetDLI`. **Ветка «нет данных» есть — это пропуск раздела, как у любого не измеренного блока отчёта.** Вопроса владельцу нет;
   - **почва:** `mlsnResults` идёт в отчёт только если это строка (`if (mlsnResults && typeof mlsnResults === 'string')`), объект-заглушка пропускается;

Это класс `GH-459`, другой предмет. Попутно: `mlsnResults` в рекомендателе на деле — HTML-строка или заглушка, поля `nutrients` нет ни у той, ни у другой, так что ветка `mlsnResults.nutrients` в Word не срабатывает никогда. **Слова «не посчитано»** — только на `/hub`: служебная панель, клиенту не видна, слова берутся из составителя пункта 79 (ключ модуля). В Word раздел без результата не печатается уже сегодня (п. 4).

## Проверка — поведением, не счётом

- **Песочница `vm` с отрисовкой** (приём пункта 79): состояние фикстуры, каждый из пяти результатов по очереди `null`, остальные — настоящие.
  - Отрисовка **не бросает**.
  - Раздел печатает «не посчитано».
  - Соседние разделы — свои числа.
  - Итого 5 случаев.
- **Положительный контроль:** тот же набор с таблицей без умолчаний, но без проверки в разделе, **бросает** — `TypeError` с именем свойства. Без этого зелёное «не бросает» ничего не доказывает. Мутацию для приёмки выбирает ревьюер. Кандидат — снять проверку одного раздела.
- **Прогон целиком:** случай на стенде оркестратора (`tests/lib/orchestrator-bench.js`). Каскад без `traffic` — событие `gaip:analysis-complete` **без** `error`, строка пишется, `metrics` на месте.

## Подводные камни

- **Не ставить `try/catch` вокруг отрисовки вместо проверок.** Он спрячет и настоящую ошибку, и провал станет молчаливым пустым экраном. Проверка — по разделу, по образцу `d`.
- **`?? null`, не `|| null`:** у упругости `FI: 0` бывает измеренным нулём. Разницу надо сохранить в самом результате, а не только в таблице.
- **Порядок внутри сдачи:** сначала проверки в отрисовке и их случаи, потом снятие умолчаний. Одна сдача, два шага. Мутация «снять проверку» показывается на дереве, где умолчаний уже нет.
- **3гр снимает `tissueResults` и `fertiliserIndex`.** 3гс снимает умолчания букв `oe` и `ne`. Если 3гр пройдёт раньше, у этих двух букв остаётся один читатель — отрисовка, и защита п. 2 их закрывает. Если позже — всё то же. Порядок между 3гр и 3гс не важен.
