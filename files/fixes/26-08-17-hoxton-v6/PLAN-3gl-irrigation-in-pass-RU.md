## Решение: (а), архитектурное — меняется ли экран при переносе, по коду

**Не меняется ни в одном месте при тех же входах. Решение аналитика — ветвь (а), владельцу не несётся.** Разбор по коду 30.09, по просьбе координатора. Прогона не было.

**Входы планировщика в отрисовке — это уже входы прохода.**
- `gaip_render_results` зовут два места, оба с состоянием и погодой самого прохода:
  - после каскада — `gaip_render_results(t, a, l, d, oe, ne, ae, me, se, le)` (`hub-tissue-v3.js`, блок «END ENGINE EXECUTION»);
  - после повтора прохода — `gaip_render_results(pass.state, pass.weather, x.l, …)` (там же, в функции публикации повтора, рядом с `window.GAIP_STATE = next`).
- Внутри отрисовки планировщик получает это состояние (`e`) и эту погоду (`t`) через `gaip_climate_get_irrigation_forecast(t, window.climateMetrics)`. `window.climateMetrics` оба пути ставят из `climateMetrics` того же прохода непосредственно перед вызовом (`window.climateMetrics = extracted.climateMetrics` и `if (x.climateMetrics) window.climateMetrics = x.climateMetrics`).

Шаг прохода с теми же тремя аргументами даёт то же число по построению.

**Три места, где отрисовка и проход могли бы разойтись, — и почему сегодня не расходятся:**
1. **Датчик влажности.** Отрисовка вливает VWC датчика, только если активная площадка страницы совпадает с площадкой датчика. В прогонщике активная площадка — площадка прогона (адрес `&site=`), поэтому проверка проходит так же, как пройдёт в проходе. На стенде VWC нет ни у одной площадки: `depletionSource = "days"` во всех 126 строках.
2. **Отрисовка не состоялась.** Сегодня такая строка остаётся без числа, после (а) число будет. Последние строки всех 13 площадок число несут; без числа 6 строк из 132, и все они не последние. На экране, который показывает последнюю строку, изменений 0. Это расхождение в сторону исправления, того же рода, что в 3аз.
3. **Объединённый экспорт.** Цикл на каждую запись делает `setActiveSite` → `triggerAnalysis()` → `await waitForAnalysis(TIMEOUT_MS)` → `we.collectData(_entryInputs)` (`word-export-combined.js`). Проход, отрисовка и чтение идут в одном кадре для той же площадки, поэтому глобал и результат прохода — одно число.

   Граница: при истечении `TIMEOUT_MS` чтение берёт прошлое значение в обоих устройствах. (а) тут не хуже, а результат прохода можно сверить с площадкой записи — глобал этого не позволяет.

**Доказательство — сравнение, которое уже стоит в ветви (а):** 13 площадок, одна погода, `weeklyNeed` и `netDeficit` из отрисовки и из прохода.
- Совпало — сдача.
- Разошлось хоть у одной — вывод «экран не меняется» неверен, работа останавливается, и вопрос владельцу пишу я, с числами по площадкам.

**Почему не (б1):** она оставляет число зависимым от отрисовки невидимой страницы. Это класс, который 3аз снял для температуры почвы.

Совпадает с моим решением 25.09 по Вопросу 142 («оставить до Вопроса 141»): тогда не хватало устройства, теперь оно есть — 3аз.

## Подводные камни

- **Условие `Bt && !Bt.error` в блоке полива отрисовки сохранить.** Сегодня оно даёт надпись «Irrigation calculation unavailable» при пустом результате. После (а) `Bt` — результат прохода, и он бывает `null`. Разворачивать его без проверки нельзя: отрисовка упадёт, и с ней весь прогон (разбор в 3гс).
- **Не оставлять второй вызов планировщика «на всякий случай»** в отрисовке: два расчёта одного с разными входами — это дефект 3аз.
- **Порядок шага.** Шаг полива до записи и после почвы. Иначе полив посчитается на пустой почве, и `omEffect` пропадёт — сегодня он есть в 46 строках, это органика у полива.
- **`computed.waterBalance` дублирует `computed.irrigation`** (недельная потребность, дефицит, расписание 7 дней). После (а) это два места в строке об одном. Сводить не в этой работе: `computed.waterBalance` читают свои читатели. Граница, названа.
- **Датчик влажности.** Отрисовка вливает VWC датчика, проверяя активную площадку страницы (`GAIP_SiteContext`). В проходе датчик берётся из входов прогона. На стенде VWC нет ни у одной площадки (`depletionSource = "days"` у всех), поэтому живьём эту ветку не увидеть — только фикстурой.
- **`daysSinceIrrigation = 1` не менять в этой работе.** До ответа владельца число прежнее, иначе замер «совпало/разошлось» смешает две причины.
