# Сверка пункта 3ви: перечень осмотренного

Ревьюер, 30.09.2026, ночь. Только чтение, правок нет. Заявка аналитика: «вызов не уходит в чужую функцию, цепочка живая».

**Исход: предмета нет, заявка подтверждается. Цепочка проверена звено за звеном, адресами.**

| звено | адрес | что увидел |
|---|---|---|
| чей объект `hub` | `climate-engine-v2.js:1020-1022` | `_getHub()` возвращает `window.GilbaHub` — тот самый объект, не чужой |
| вызов | `climate-engine-v2.js:962` | `await hub.orchestrator.computeSelective('climate')` |
| принимающая функция | `gilba-hub-v2.js:970` | `async computeSelective(e)` — метод оркестратора `GilbaHub`, живой |
| выбор движков по входу | `gilba-hub-v2.js:869-883` | `getAffectedEngines` ищет по индексу входов и по корню ключа, потом идёт вниз по зависимостям |
| попадает ли климат в выборку | `climate-engine-v2.js:482` | движок объявляет `inputs: ['climate', 'turf', 'site', 'soilTemp', 'sensor']` — индекс его найдёт |
| регистрация движка | `climate-engine-v2.js:1151-1154` | `hub.engines.register({ ...ClimateEngine, compute: ClimateEngine.compute.bind(ClimateEngine) })` |

## Что стоит записать при закрытии, иначе через месяц прочитается как противоречие

`hub-orchestrator.js:5783` говорит прямо: `computeSelective`, `computeIsolated` и `executeEngine` **старого оркестратора** сняты по `GH-718` / `GH-755`. Одноимённый метод жив только у `GilbaHub` (`gilba-hub-v2.js:970`).

То есть путаница возможна не в коде, а при чтении: **одно имя у двух оркестраторов**, и снятое — не то, которое здесь зовётся. Без этой строки закрытие пункта выглядит противоречащим записи о снятии.

## Границы этой сверки

- Сверка **статическая**: я читал код и разметку страниц, живого прогона не делал, событие `climate:metrics-ready` и порядок вызовов во времени не мерил.
- Не проверял, что `_inputIndex` действительно содержит ключ `climate` в момент вызова — это свойство исполнения, а не текста; из объявления `inputs` следует, что должен.
