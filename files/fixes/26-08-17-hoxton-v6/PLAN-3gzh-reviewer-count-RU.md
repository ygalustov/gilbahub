Ревьюер, 30.09.2026, ночь. Только чтение и `SELECT`. Числа аналитика считал заявками.

## Единица

**Множитель = одно поле в объекте `modifiers`, которое движок кладёт в результат.** Для экспорта — **два разных счёта**, и их нельзя смешивать: сколько полей он **забирает** и по скольким **решает печатать**.

## Счёт по коду

**Движок пишет девять множителей** (`wear-recovery-engine-pure.js:1084`): `growth`, `shade`, `rootDepth`, `soilHealth`, `moisture`, `nitrogen`, `salinity`, `temperatureStress`, `poa`. Девять — совпадает с заявкой аналитика.

**Экспорт забирает девять из девяти** (`word-export.js:10107-10118`) — кроме `poa`, то есть восемь по имени плюс два составных (`nitrogen`, `salinity` с вложенными `factor`).

**Но решает печатать по трём** (`word-export.js:14687-14689`):

```
var hasStressFactors = (rm.salinity && rm.salinity.factor > 1) ||
                       (rm.shade && rm.shade > 1) ||
                       (rm.temperatureStress && rm.temperatureStress.factor > 1);
```

**Рост и азот в условие не входят вовсе.** Поэтому площадка, у которой удлиняют срок именно они, забирает данные и не печатает раздел.

**Поправка к формулировке заявки:** «экспорт ждёт `<0.8`» я не подтверждаю — порог `0.8` в этом условии не участвует. Сравнения `< 0.85` есть, но в другом месте (`word-export.js:6890`, `:6905`, `:6921`, `:6936`, `:6950`) и это рейтинги «Excellent / Good», а не условие печати раздела. То есть дефект не в перевёрнутом пороге, а в **неполном перечне**: три поля из девяти решают за все девять.
