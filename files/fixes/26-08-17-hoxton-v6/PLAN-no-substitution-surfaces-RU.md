## 2. Корневая причина

Координаты (и дальше — температура, вид, ростовой потенциал) обрабатываются как **вход с умолчанием**, а не как факт с
исходом: каждый потребитель сам решает, чем заткнуть пустоту (`|| -33.87`), и ни одна поверхность не знает, что число
внизу посчитано не из данных площадки. Собственный прогон страницы (вид II) считает на подставленном и кладёт результат
в состояние, откуда его печатают документ и экраны без происхождения. Это тот же класс, что GH-459 (число о другом
месте под именем площадки), только место выбрано не гонкой, а константой.

## 3. Устройство — одно правило на все поверхности

Координаты — факт площадки с владельцем (строка `sites`, GH-473) и **исходом** по двадцать восьмому: `present` / `empty`
(в строке `NULL`) / `unavailable` (строка не прочитана — причина). Всё производное — регион, полушарие, нормали, GP,
риск болезней, орошение, стресс-каскад, сезонные окна — **наследует худший исход входов**; при `empty` ничего не
считается и не подставляется. Поверхность показывает **не число и не пустоту, а исход с причиной и адресом
исправления**. Что именно — по поверхностям:

1. **Документ (одиночный и комбинированный).** Разделы, в замыкании зависимостей которых координаты, — опущены; на месте
   каждого — абзац образца GH-367 «Not included: <раздел> — site location is not set (Settings › Location)»; в реестре
   «Data availability» — **одна** строка о причине с колонкой «Sections affected», где список разделов **выводится** из
   карты покрытия (тридцать четвёртое), не набирается: Climate & Growth Conditions, Monthly Schedule (GP), Disease Risk,
   Irrigation/Water Balance, Stress Trajectory, Performance Impact и что ещё найдёт обходчик. Число в документе ни
   одно не посчитано из `-33.87`.
2. **Экраны db-shell** (`dashboard`, `analysis`, `plan`, `reports/*`, `data`): одно уведомление в шапке страницы из той же
   карты исходов — «Location is not set for this site. Climate-dependent analysis is not computed. Set it in Settings ›
   Location» (ссылка на форму); каждая карточка, зависящая от координат, показывает «Not computed — location not set»
   вместо чисел и не рисует графиков; кнопки, которым нужны координаты (Run Analysis, Generate Nutrition Program,
   Generate & Download), при нажатии отвечают по предикату сорок девятого — что не запустилось и почему, разностью
   экрана, — а не молчат и не считают на подставленном. Сообщения — из одной таблицы `REASON_TEXT` (поправка к
   двадцать восьмому), не по месту.
3. **Собственный прогон страницы и каскад (`cascade-orchestrator.js`, `hub-tissue-v3.js`, `hub-orchestrator.js`).** Входы
   каскада строятся из карты исходов: температура, GP, вид, координаты — либо значение, либо `null` с исходом; при `null`
   соответствующая ветвь каскада **не запускается**, результат несёт исход, не число. `|| 20/10/30`, `|| 'couch'`, `||
   'C4'`, `|| 50`, `|| -33.87` — уходят все. Результат прогона пишется в состояние **с исходом** (`{value: null, outcome:
   'empty', reason: 'no-coordinates'}`), чтобы документ и экраны читали причину, а не пустоту.
4. **Кэш анализа и Re-run.** Ключи, посчитанные на подстановке, в кэш не пишутся: при `empty` ключ отсутствует, рядом —
   исход; сервер (`SampleAnalysisController`, dashboard) не показывает старые числа как текущие: у записи кэша есть
   `computedAt` и исход входов, страница печатает «not computed» а не последний кэш.
5. **Сценарии и what-if** (`gaip/gssh-scenario-engine.js:319, 456`, `gaip/gssh-whatif-ui.js:489-490`): `lat: -33.87` там —
   **сид демо-сценария**, объект, который пользователь видит и правит; это другой предмет, чем подстановка при расчёте
   (`:762`, `:934`, `:754`, `:750`). Устройство: сценарий берёт координаты площадки (по id, как всё владение), а при их
   отсутствии не создаётся — форма сценария показывает тот же ответ, что п. 2; сид с Сиднеем как «пример» — доменный
   вопрос владельца (раздел 6), до ответа — как есть, но в инвентаре как подстановка с ценой.
6. **Вход — закрыть с обеих сторон.** Сервер: `latitude`/`longitude` — `required` в `store()` и `update()`
   (`SiteController.php:90-91, 166-167`) с сообщением, совпадающим с формой GH-404; `syncRegistry()` площадку без координат не
   создаёт (уходит с GH-439 стадией 2); мастер — шаг локации обязателен для завершения (проверить, так ли сегодня; по
   grep требования не нашла). Тогда `empty` у координат становится состоянием, которого у новой площадки не бывает, а
   устройство п. 1–5 остаётся защитой для старых данных и для чтения `unavailable`.

**Что упраздняется** — все 24 строки таблицы и четыре подстановки каскада; не «понижаются» и не «переносятся в одно
место». Единственное разрешённое умолчание в проекте — два названных исключения 10.7 (сертификат S277, порог P = 21), и
ни одно из них не о координатах.

## 5. Подводные камни

- **`|| -33` в проверке полушария** (`irrigation-scheduler.js:263`, `event-planner-engine.js:459-460`): при `null` выражение
  `(null || -33) < 0` даёт «южное» — тихо и всегда; после снятия `null < 0` даёт `false` = «северное» — **вторая
  подстановка на месте первой**. Полушарие — производный факт с исходом; при `null` не «северное», а «не определено».
- **Лесенки** (`hub-tissue-v3.js:2330`, `:6672` — `Math.abs(lat || -33)` уходит в широтные пороги): по пятьдесят седьмому
  первая ветвь — `null → null`, субъект без подстановки.
- **Классификатор NZ** (`gh362`, `isNZCoordinates`): `false` при неизвестных координатах — булево умолчание; отвечать `null`
  (двадцать третье); потребители трёх состояний.
- **`GAIP_HUB_CONFIG.activeSiteId`/страница как источник координат** (`hub-orchestrator.js:3885` читает
  `GAIP_CANONICAL_STATE.climate.lat || GAIP_STATE.climate.lat || GAIP_STATE.turf.lat || -33`): снятие `-33` оставляет
  чтение состояния страницы — класс GH-459; координаты читаются по id из строки площадки (GH-473/474), как в экспорте.
- **Похожее, но не это:** `hoxton-climate-normals-service-ensure.test.js:350` — Сидней как **вход** фикстуры, не умолчание;
  `regional-profiles.js:1294-1300` — широтные умолчания региона (двадцать третье, уже в работе как подстановка последним
  `return`); константа `50` — пятьдесят восьмое, один класс на 11 мест, здесь не дублируется.
- **Второй кэш и гонка**: результаты прогона с исходом должны доходить до документа тем же путём, что сегодня числа
  (`GAIP_STATE.*`, `climateMetrics`), — иначе документ прочтёт старое число из состояния; исход пишется в то же место,
  что число, а не рядом.
- **Тесты, закрепляющие Сидней как выход:** по grep не нашла; но фикстуры песочницы (`store-shapes`, `e2e-parity-*`)

  затронутых разделов (п. 3.1), не перечень из головы.

## 6. Как проверить

- **Дифференциальный прогон по входу «координаты»** (пятьдесят четвёртое): фикстура площадки A с координатами → полный
  документ; та же фикстура с `latitude = null` → в `word/document.xml` ни одного числа из замыкания зависимостей координат
  (обходчик покрытия), абзацы «Not included: … location is not set» на местах разделов, одна строка реестра с
  «Sections affected» — список равен множеству разделов, чьи числа исчезли (равенство в обе стороны); положительный
  контроль — прогон с координатами печатает их все. Мутация ревьюера: вернуть `|| -33.87` в любой из 12 файлов → в
  пустом прогоне появляется число → красный.
- **Экран:** страница `dashboard`/`analysis` на площадке без координат (сеется в базе напрямую — форма не даст): уведомление
  в шапке есть, карточки климата/болезней/орошения показывают «Not computed — location not set», ни одного числа; клик
  Run Analysis — разность экрана называет действие и причину (сорок девятое); парный обычный прогон на той же площадке с
  координатами — числа есть, уведомления нет.
- **Каскад:** песочница `cascade-orchestrator` с `climateMetrics = null`, `turf.grassSpecies = null` → результат каскада
  несёт исход, не числа; мутация — вернуть `|| 10` → число → красный.
- **Полушарие:** фикстура без координат → сезонные окна не считаются (ни южное, ни северное); фикстура с северной
  широтой → северное; мутация «`null < 0`» → «северное» при пустоте → красный.
- **Вход:** `POST /api/sites` без координат → 422 с тем же текстом, что GH-404; мастер не завершается без локации.
- **Реестр:** документ площадки с координатами не несёт строки о локации (положительный контроль тридцать третьего).
- **Инвентарь подстановок:** прогон «все, кроме одного» (сорок четвёртое) по входу `latitude` обязан дать в стоках ноль
  подставленных чисел; сегодняшние 24 строки — записи «в оценке, цена 0 из 12» до правки, «снято по решению» после.
