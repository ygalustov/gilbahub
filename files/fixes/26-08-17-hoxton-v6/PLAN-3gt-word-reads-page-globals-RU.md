## Доходит ли чужая площадка до печати — да, в объединённом экспорте, по коду

**Цепочка:**
1. Цикл объединённого экспорта на каждую пробу делает `setActiveSite` → `triggerAnalysis()` → `await waitForAnalysis(TIMEOUT_MS)` → `we.collectData(_entryInputs)` (`word-export-combined.js`).
2. **`waitForAnalysis` не различает исходов.** Он завершается по `gaip:analysis-complete` — и с `detail.error`, и без. По таймауту `TIMEOUT_MS = 15000` он тоже завершается, со словами `warn('Analysis timed out after', timeoutMs, 'ms, collecting what we have')`.
3. **Прогон, который упал, глобалы не переписывает.** Отрисовка и публикация `GAIP_STATE` стоят в `try` до события. При исключении `catch` шлёт событие с ошибкой, и публикации нет (разбор в 3гс).
4. **Смена площадки результаты не чистит.** `site-switch-cleanup.js` сбрасывает только идентичность газона (якорь `global.GAIP_STATE = { inputs: { turf: cleared } };`). `GAIP_STATE` — геттер, который отдаёт последнее записанное (`tests/fixtures/page-state-shapes.json`, `_how`).
5. **Итог:** у пробы площадки B, чей прогон упал или не уложился в 15 с, `collectData` берёт климат, тень и статус почвы **площадки A** — предыдущей в цикле. Документ печатает их под именем B. Это цена `GH-459` в её исходной форме: чужой климат под своим именем.

**Одиночный экспорт не затронут.** Там площадка документа и есть площадка страницы: `collectData`, якорь «there is one caller for which the page's site IS the document's site (exportToWord)».

**Сколько площадок и какие разделы.**
- **Разделы:** климат — у каждой пробы; тень — у пробы, если у A был `currentDLI` (в строках тень есть в 126 из 132); строка «Status» почвы — если у A был результат MLSN (91 из 132); погода поправок.
- **Площадки:** любая, кроме первой в выгрузке. Условие — прогон её пробы в цикле не опубликовал результат.
- **Как часто прогон не публикует — по строкам:** 5 провалов из 132. Три `run-not-completed` у Test5 22.09 и два `calculation-error` 29.09 в 10:25:10 (Russley) и 10:25:31 (Test5), с разницей в 21 с. Шли ли они внутри выгрузки, по базе не видно. Таймаут строкой не отмечается: прогон может дописаться позже, когда документ уже собран.
- **Не измерено:** напечатала ли хоть одна настоящая выгрузка чужой климат. Для этого нужен живой объединённый экспорт с принудительным провалом одной площадки — окно пункта 14.

## Корневая причина

Цикл объединённого экспорта считает прогон своей площадки состоявшимся по факту **события**, а не по его **исходу**. После этого он читает однослотовые глобалы, которые принадлежат последнему **удачному** прогону, а не этой площадке. `GH-498` уже закрыл тот же разрыв для конфига («the fact, or an outcome»). Для прогона — нет.

## Устройство

**1. Ворота на исходе прогона — закрывают класс целиком, одним местом.** Это предмет пункта.
- `waitForAnalysis` возвращает исход: `{ ok: true }`, `{ ok: false, reason: 'calculation-error', message }` (из `detail.error`) или `{ ok: false, reason: 'timed-out' }`.
- Цикл при `ok: false` пробу **не печатает из глобалов**. Он поступает так, как уже поступает при несостоявшемся конфиге (`GH-498`, якорь `warn('Config not applied for ' + … + ' — sample ' + entry.sampleId + ' skipped');` и `continue`): проба пропускается с названной причиной, и причина попадает в итог выгрузки.
- Так чужая площадка не доходит до печати **ни в одном разделе** — климат, тень, почва, погода поправок и полив (до 3гл) закрываются разом. (2)

**2. Названные чтения — из результата прохода своей площадки, а не из глобала.** Ворота 1 делают их верными по площадке, но источник остаётся слотом страницы. По правилу проекта печатаемое берётся из данных объекта.
- Климат (2 места) и тень (1) — из `computed` прохода, которого только что дождался цикл. Путь тот же, что 3гл берёт для `computed.irrigation`.
- Строка «Status» почвы — из `computed.soilNutrition.verdict` той же строки прохода, а не из разбора HTML. Слово на выходе то же. (4)

**3. Мёртвая ветка `mlsnResults.nutrients` — не чинить в этой работе, назвать.**
- `recommendSoilAmendments` (`soil-tissue-integration.js`, якорь `if (mlsnResults && mlsnResults.nutrients)`) ждёт объект со списком нутриентов, а получает HTML-строку или заглушку. Ветка не срабатывала никогда.
- Оживить её — значит изменить рекомендации поправок в Word у всех площадок. Это продукт, решение владельца, с числом по площадкам.
- В 3гт вход поправок переводится на результат прохода (п. 2), **поле `nutrients` не добавляется** — поведение прежнее. (0)

## Что человек видит вместо пропущенной пробы — замер 01.10

**Пропуск по `GH-498` выводится только в консоль.** В цикле он пишется двумя вызовами: `console.warn('[CombinedExport] GH-498: …')` и `warn('Config not applied for ' + … + ' skipped')`. А `warn()` — это тоже только консоль (`word-export-combined.js`, `function warn()` → `console.warn.apply(console, args)`). Человек этого не видит.

**Что он видит:**
- **окно хода** (`createProgressUI`) считает все выбранные пробы: `progress.update(i + 1, entry.siteLabel, …)` доходит до N, конец — `progress.finish('Download ready!')`. О пропуске ни слова;
- **документ** нумерует отчёты по включённым: `'Report ' + (r + 1) + ' of ' + reports.length`. Выбрано 12, пропущена одна — в документе «Report 1 of 11 … 11 of 11», без пустого места и без отметки, какой пробы нет.

**Три последствия, как их различает координатор:**
- **сегодня, без ворот:** на месте пробы B — **прежние числа**, климат и тень площадки A под именем B. Человек примет их за свои. Худший случай;
- **с воротами по образцу `GH-498`, как есть:** **ничего** — раздела B нет, пустого места нет, нумерация сомкнута. Человек может не заметить, что проба не вошла;
- **нужно:** пропуск виден там, где человек смотрит.

**Поэтому вынос причины в итог входит в эту работу** — и для нового пропуска (прогон), и для существующего (`GH-498`, конфиг): у них один выход.
1. **Окно хода в конце** называет пропущенные пробы: площадка, проба, причина («analysis did not complete», «timed out», «site settings were not applied»). Итог — «Download ready — N of M samples included». (1)
2. **Документ** несёт строку о непопавших пробах: в оглавлении или в начале — какие пробы выбраны и не вошли, и почему. Нумерация отчётов остаётся по включённым, строка о пропуске её объясняет. (1)

**Слова.** Строка в документе — клиентский текст.
- Для «прогон не состоялся» у составителя уже есть фраза несостоявшегося повтора (`dashboard-ui.js`, якорь `'The re-run{when} did not complete: {reason}. Try Re-run again.'`, из `GAIP_ANALYSIS_TEXTS`). Для документа она не годится дословно: «Try Re-run again» в выгрузке не к месту.
- **Проверено 01.10: у составителя (`AnalysisNotice.php`) такой фразы нет.** Есть только фраза несостоявшегося повтора (`FAILURE_FRAME`) и фраза об исчерпанном PGR («… and is not included in this analysis.»).
- **Но в самом Word есть объявленный реестр «не вошло», `GH-488`:** исходы (`OUTCOME_STATUS` — `empty` «Not set», `unavailable` «Could not be read», `omitted` «Not included»), коды причин и одно место для их человеческой половины (`REASON_TEXT`). Строка на месте раздела — `_notIncludedLine`: «Not included: {что} — could not be read ({причина}). This is not a statement about the site.».
- **Пропуск пробы ложится в этот реестр.** Три новых кода причин — прогон не состоялся, не уложился во время, конфиг не применён — и строка на уровне документа, а не раздела: у пропущенной пробы раздела нет. Рамка готова, новые — только три текста причин.
- **Тексты причин — клиентские слова, поэтому вопрос владельцу.** Файл дословно: `QUESTION-owner-export-skipped-sample-words.md` (скрэтчпад аналитика), варианты (а)/(б)/(в). До её ответа — окно хода с причиной (п. 1): это экран выгрузки, не документ.

### Запись факта пропуска — граница, размер назван

**Места, куда писать, на сервере нет.** Ни таблицы выгрузок, ни маршрута записи для экспорта: `SHOW TABLES` — только `field_log_entries` и `spray_logs` по шаблону `log`; в `app/routes/web.php` записи для выгрузки нет.
- **Частичный след уже есть:** прогон, упавший внутри выгрузки, прогонщик записывает строкой `failed` (`calculation-error`). Это ровно та причина, по которой ворота пропустят пробу. Не пишется таймаут — прогон допишется позже как удачный — и сам факт, что выгрузка пробу пропустила.
- **Если записывать:** миграция таблицы выгрузок (1), модель и маршрут с контроллером (2), вызов из цикла по итогу выгрузки — «намерение, не состояние»: какие пробы выбраны, какие пропущены и почему (1), тест (1). **≈ 5 мест.** 3гт вырастает с ≈ 10 до ≈ 15.
- **Моё предложение — не включать в 3гт.** Предмет пункта — чтобы чужое не печаталось и пропуск был виден человеку. Запись нужна, чтобы отвечать «сколько раз», а это другой вопрос. Если не включать, граница остаётся названной: **после сдачи на вопрос «сколько раз это случалось до» ответа по-прежнему не будет, а вперёд он будет только частичный — по строкам `failed`.** Решение — за координатором.

## Пересечения

- **С 3гз — нет, механизм другой, работа не одна.**
  - 3гз — клиентские страницы почвы и водного баланса вливают ответ сервера о выбранной пробе в глобал строки (`GAIP_DASHBOARD_DATA`): та же площадка, другая проба.
  - 3гт — Word в спрятанном прогонщике читает однослотовые глобалы результата, которые после несостоявшегося прогона принадлежат другой площадке.

  Класс один — `GH-459`, печать состояния страницы под видом данных объекта. Но общих мест кода нет, и лечится разным: там — своя переменная просмотра, здесь — ворота по исходу. Ключ водного баланса без идентификатора площадки (`gilba_wb_active_soil`) — предмет 3гз: он про выбор пробы в браузере, а не про результат прогона.
- **С 3гл — да, по полю полива.** Word читает `window.GAIP_IRRIGATION_RESULT` тем же образом. 3гл переводит его на `computed.irrigation`. Ворота 3гт защищают и полив, пока 3гл не сдан. Порядок любой.
- **С 3гс — да, по источнику.** Чтения Word тени и почвы из глобала вынесены из 3гс сюда. 3гс меняет, **что** лежит в глобале, если прогон не дал результата (`null` вместо заглушки). Ворота 3гт — **чей** это прогон. Друг от друга не зависят.

## Подводные камни

- **Пропуск пробы меняет документ:** в нём будет меньше разделов, чем выбрано проб. Прецедент — `GH-498`, тот же цикл. **Проверено 01.10: `GH-498` пишет только в консоль**, итог выгрузки и документ о пропуске молчат. Вынос — в эту работу, раздел «Что человек видит вместо пропущенной пробы».
- **Не превращать таймаут в ожидание дольше.** Удлинение `TIMEOUT_MS` уменьшает частоту, но оставляет механизм. Ворота — на исходе, а не на времени.
- **Прогон, дописавшийся после таймаута,** запишет свою строку позже. Документ уже не будет его ждать. Это верно: проба пропущена с причиной «не уложился».
- **Координаты по умолчанию рядом** (`if (!isFinite(_lat)) { _lat = -33; _coordsDefaulted = true; }`, «Sydney-ish default») — подстановка того же файла, но другой класс. Она объявлена через `coordinatesDefaulted`. Не входит, названа.

## Как проверить

- **Стенд объединённого цикла** (песочница `vm` над `word-export-combined.js`, две пробы, A и B, с разными климатами):
  - B получает событие `gaip:analysis-complete` с `detail.error` → проба B **не печатается**, в итоге выгрузки названа с причиной, климат A в разделе B отсутствует;
  - B не получает события 15 с → то же, причина «timed-out»;
  - B удачна → раздел B несёт климат B, а не A. Сравнение с фикстурой B, а не с разделом A.
- **Положительный контроль:** без ворот первый случай печатает у B температуру A. Число из фикстуры A, названо в выводе. Мутацию для приёмки выбирает ревьюер. Кандидат — вернуть `resolve()` без исхода.
- **Живое подтверждение** — одна объединённая выгрузка с принудительно упавшей площадкой, в окне пункта 14.

## Признак сдачи — числом

- Чтений результата из глобала в Word: 5 → 0 (климат 2, тень 1, почва 1, поправки 1).
