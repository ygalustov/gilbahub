**Рамка — решение владельца 23.09** (`CLAUDE.md`, «В коде ссылок на вопросы нет. Только `GH-NNN`»): связь кода с документом держит номер задачи, который не меняется никогда; имя или номер в документе меняются. Решение координатора 30.09 распространяет это на имена пунктов очереди.

## Признак — что считается «именем пункта в коде», замер форм

Сейчас в дереве (`assets`, `app/app`, `app/resources`, `app/database`, `tests`):

| форма | пример | вхождений | что с ней |
|---|---|---|---|
| **Ф1** `queue item <имя>` | `GH-787 (queue item 3vy)`, `GH-777 (queue item 4)` | **608** (замер 01.10; было «492») | **входит**: имя пункта — и транслитерация (`3vy`, `3ga`…), и номер (`4`, `7`, `9`…) |
| **Ф2** `(item <имя>` после номера задачи | `GH-663 (item 3x)`, `GH-710 (item 3ac)` | **55** (замер 01.10; было «≈ 40») | **входит**: та же ссылка без слова `queue` |

## Как сторож отличает подпись от предмета

Строка `queue item` в 97 наборах — **подпись самого набора** (шапка-комментарий), предметом она нигде не является (проверено координатором до заведения). Предметом она станет в самом стороже и в его фикстуре: тест, который ищет подписи, держит образцы признака строками. Поэтому признак ищется **только там, где живут подписи**, по типу файла:
- **`.js`** — только в комментариях: `commentsOf` из помощника 3гд (`tests/lib/source-without-comments.js`, `GH-788`). Строки и регулярки — код и предмет, туда не смотрим. Файл, который `@babel/parser` не разбирает, — бросок с именем (правило помощника), а не молчаливый пропуск;
- **`.php`** — только комментарии (`//`, `#`, `/* */`). Разбор — токенизатором PHP через `php -r 'token_get_all(...)'` в том же прогоне; нет `php` — бросок с причиной. Если это сочтут тяжёлым: в 13 файлах PHP подписи по форме `// GH-NNN (queue item …)`, строк-литералов с этими словами там нет (проверяется первым прогоном). Тогда простой лексер комментариев — решение разработчика, печатается в шапке прогона;
- **`.json`** — все строковые значения: в JSON нет кода, подписи живут в `$comment`, `why`, `reason`. Исключение одно — фикстура самого сторожа (её предмет — эти строки), по имени файла;
- **`.blade.php`** — комментарии Blade `{{-- --}}` и HTML `<!-- -->`, плюс блоки `<script>` через `commentsOf` (тот же приём, что 3вг, сдача 2).

**Граница, найденная замером 01.10 — строковые данные JS.** Имя пункта стоит и в прозе внутри данных: `tests/gh532-no-live-test-without-stand-protection.test.js:97`, значение `why:` в карте исключений, `'… queue item 4 declares the requirement …'`. По правилу «в `.js` — только комментарии» сторож его не видит. Расширять правило на все строки JS нельзя: тогда предметом станут строки-образцы в самом стороже и в тестах, и различение подписи и предмета рухнет. **Устройство:** строковые литералы JS с признаком сторож печатает отдельным списком «в строковых данных, не подпись и не предмет», без красного — по требованию 30.09 печатать то, что не осмотрено как подпись. Сегодня одно место.

## Четыре оси — как ревьюер их задал, и чем каждая заполняется

- **Единица — одно вхождение с адресом, не файл.** Ключ остатка — `файл | нормализованный текст подписи #n`, а не номер строки: строка уезжает с каждой правкой файла (урок `nutrition-calendar.js:3207` → `:3231`). Адрес `файл:строка` вычисляется при прогоне по ключу и печатается в каждой строке вывода (приём `addressOf` из `gh746`, но по `commentsOf`, чтобы адрес не указал в код).
- **Момент — прогон набора**, тот же, которым автор проверяет правку (`npx jest`), без отдельного шага.
- **Различимость.** Красное называет адрес и имя. В шапке каждого прогона: сколько файлов прочитано по каждому типу, сколько разобрано, сколько подписей найдено, версия признака. Зелёное без этой шапки неотличимо от «до предмета не дошли».
- **Вход — остаток перечнем адресов.** Красное в двух случаях:
  1. **новая подпись** — ключа нет в остатке;
  2. **остаток уменьшился** — ключ в остатке, а в дереве его нет.

  Второе — чтобы остаток оставался правдой: убравший подпись убирает и её строку из фикстуры в той же правке, и это видно в отличии фикстуры.

## Что сторож делает с остатком — не чинит, печатает

При каждом прогоне сторож печатает остаток: число и, **отдельным списком, неоднозначные подписи**.

Иначе новая подпись группы, которой сегодня в коде нет, пройдёт как однозначная. ## Проверка

- **Контроль зелёным** на дереве после правки: шапка с числами, остаток равен фикстуре.
- **Мутации выбирает ревьюер.** Образцы:
  - новая подпись `GH-999 (queue item 3xx)` в комментарии любого файла — красный с адресом;
  - та же строка **внутри строкового литерала** теста — **не красный** (предмет, не подпись). Это доказывает, что сторож отличает одно от другого;
  - удалить одну подпись из остатка в дереве, не трогая фикстуру, — красный «остаток уменьшился» с ключом;
  - файл `.js`, который не разбирается, — бросок с именем, а не зелёный;
  - новый файл `tests/fixtures/q99-….json` — красный по Ф4 с путём; тот же номер внутри комментария файла без номера в имени — Ф4 молчит, красное даёт Ф1/Ф2;
  - подпись с апострофом `GH-999 (queue item 3xx's …)` в комментарии — красный (так ловится `hub-tissue-v3.js:1180`);
  - `queue item 3xx` в значении `why:` объекта JS — не красный, но строка в списке «в строковых данных».
