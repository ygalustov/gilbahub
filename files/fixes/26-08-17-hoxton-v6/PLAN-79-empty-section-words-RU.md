## Решение координатора 30.09: вселенная признака — НАПЕЧАТАННОЕ на страницах. Устройство признака

**Её слова:** «вселенная — напечатанное на страницах, а не литералы в файлах… признак „стало 0“ считается по тому, что страница отрисовала человеку, и снимается отрисовкой, а не `grep` по строковым литералам». Правило проекта ровно на это: перечень от кода обходится новым местом записи, вселенная от напечатанного — нет.

**Что это меняет в плане выше:**
- **26 мест в 7 файлах — перечень предмета, вход правки.** Не признак.
- **Раздел «Признаки — переписаны в местах» заменяется этим.** Числа «26 → 0», «3 → 0» остаются как проверка правки по перечню, но сдача принимается по напечатанному.

### Чем снимать отрисовку — замер оснастки

- **`jsdom` в дереве нет** — ни в `node_modules`, ни в `package.json`. Jest работает в среде `node` (`jest.config.js`, `testEnvironment: 'node'`). Добавить пакет — отдельное решение, в пункт не беру.
- **Готовый приём в дереве есть** — песочница `vm`, в которой исполняется исходник страницы. Функции отрисовки пишут HTML в контейнер или возвращают строкой. Так уже тестируются почва (25 наборов, например `vm.runInContext(testSrc, ctx, { filename: 'soil-nutrition-analysis.js' })`), вода (2), болезни (7), Growth & Light (7), `/plan` (6), дашборд (5).
- **У страницы стресса (`stress-analysis.js`) наборов нет ни одного** — песочница для неё новая, одна.

### Признак

1. **Исполнитель напечатанного — одна песочница на страницу**, общий помощник в `tests/lib/`.
   - Он исполняет страницу и зовёт её **входную** отрисовку: почва — `render`; вода — отрисовку страницы, для пустого раздела `renderEmpty(container)`; стресс — `renderEmpty(container)`; болезни — `renderPage()`; Growth & Light — отрисовку страницы; `/plan` — отрисовку разделов; дашборд — `openPanel(key)`.
   - Контейнер — заглушка, ловящая `innerHTML`.
   - **Напечатанное — текст HTML без тегов, с раскрытыми сущностями** (`&amp;` → `&`), по каждому пустому разделу.
2. **Три состояния на каждый пустой раздел — из фикстуры строки, не из литералов:** анализа не было; анализ был, причина не записана; причина записана. `GAIP_ANALYSIS_TEXTS` в песочницу кладётся ответом составителя для этой фикстуры, как его отдаёт сервер (`partials/analysis-pill.blade.php`).
3. **Что утверждается, по напечатанному:**
   - в напечатанном нет «Hub» — 0 на всех страницах и во всех состояниях;
   - напечатанный текст пустого раздела **равен ответу составителя** для этого места и состояния — сравнение с ответом сервера на фикстуре, а не с копией фразы в тесте;
   - «run / re-run» печатается только там, где составитель его вернул: записанная причина класса «не досчитал» или слова, которые владелец решила не менять.
4. **Печать осмотренного** (требование 30.09 к сторожам): страниц исполнено, разделов, состояний; и отдельно — чего не осмотрено.

### Исключения признака — все семь по решению координатора, плюс два порождения

Это строки, которые читает код. Правка их как фраз ломает проверку — замер ревьюера. В напечатанном они могут встретиться и из признака исключаются **поимённо, по тексту и месту**, а не по шаблону:

## ПОПРАВКА 01.10 — по возврату `GH-792`: два пробела признака, один мой полностью, один по форме

Ревьюер вернул сдачу. Под двумя его мутациями набор остался зелёным:
- слова составителя проверены на проводимость (страница печатает то, что вернул составитель), но не на совпадение с утверждёнными — класс `GH-409`;
- вселенная набора взята из списка в теле теста, а не из объявленного перечня `AnalysisNotice::sections`.

**Разбор по плану.**
- **Вселенная — мой пробел.** Раздел «Признак» (решение координатора 30.09, пункт 2) пишет «по каждому пустому разделу» и не называет, откуда берётся перечень разделов. Объявленный перечень в дереве есть: `app/app/Support/AnalysisNotice.php`, `public static function sections(?array $projection)`. Это ключи-потребители схемы (`AnalysisResultSchema::consumerKeys()`) плюс места без ключа результата из `WORDS_WITHOUT_A_REASON`. План должен был назвать его источником вселенной — и не назвал.
- **Утверждённые слова — требование было, форма слабая.** В «Признаке сдачи» стоит: «Составителю: … утверждённый текст, литералом из её перечня». Раздел 30.09, пункт 3 («равен ответу составителя») задавал проверку страницы и составителя не заменял. Но это не было сказано. А «литералом» разрешает переписанный в тест список — тот самый образец, против которого правило «брать ожидания из объявленного источника».

**Что признак требует теперь — две проверки, и они разные:**
1. **Составитель против решения владельца.** Ожидания — из записи решения, а не из тела теста: фикстура `tests/fixtures/gh-792-approved-empty-section-words.json`. В ней ключ места, утверждённый текст дословно по-английски и дата решения (29.09.2026). Составитель по каждому ключу своей таблицы возвращает ровно текст фикстуры.
   - Ключ в таблице без записи в фикстуре — красный.
   - Запись в фикстуре без ключа в таблице — красный.
   - Фикстуру меняет только решение владельца; правка слов в `AnalysisNotice.php` без неё краснит набор.
   - Если в таблице составителя стоят места, чьи слова владелец решила не менять (№ 9, 10, 15, 18, 19, 21), они записаны в фикстуре со старым текстом и пометкой «не менять» — это тоже её решение. Стоят ли они в таблице, я не проверяла.
2. **Страница против составителя** (проводимость, как сдано). **Вселенная — `AnalysisNotice::sections($projection)` на фикстуре строки, а не список в тесте.** Набор перебирает все ключи этого ответа, у которых есть страница-потребитель, и по каждому печатает: ключ, страницу, состояние, напечатанное. Ключ ответа, для которого не нашлось ни страницы, ни объявленного исключения «страницы нет», — красный. Так новый раздел, добавленный в перечень, без случая не проходит.
