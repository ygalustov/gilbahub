## Проблема

`waterEngine` (`assets/hub-tissue-v3.js`, `:4827`) читает вход так:

```
var t = (e.water && e.water.ions) || {},
    r = safeNum(e.water.ecw, 0),
    n = safeNum(e.water.pH, 7);
```

Отсутствующая проводимость становится `0`, отсутствующий pH — `7`, отсутствующие ионы — нулями. Дальше `A = r < 0.7 ? "Low salinity risk" : …` (`:4868`). Проход зовёт движок на каждой площадке. Узел `water-blender` в `assets/dependency-graph.json` объявляет `"requires": []`, и ворота прохода (`cascade-orchestrator.js`, `const engines = requested.filter(`, `:733`) его не снимают.

**Замер, `SELECT` по `analysis_results`.** Условие: строки, у которых `computed.water` — строка, сгруппированы по числу **неудалённых** проб воды у площадки. На момент прогонов это то же самое: у единственной площадки с удалёнными пробами воды, Federal Golf, все пять удалены до 15.07.2026, а её прогоны идут с 23.09.

Клиент видит сегодня отсутствие сообщения, а не «Low salinity risk». После правки на 6 площадках появится одно сообщение (ниже).

## Корневая причина

Модуль воды не объявляет, без чего не работает, и движок подставляет нули вместо отсутствующего. Класс тот же, что был у почвы и ткани до `GH-777` (ломтик 3): «движок считает на пустом входе и отвечает как на измеренном». Устройство для этого класса в дереве уже есть:
- **ворота графа** — `hub-orchestrator.js`, `absentRequirementsOf` (`:1769`), `inputIsThere` (`:1783`). Требование вида `samples.<вид>` спрашивается у пробы, которую прогону назвал сервер (`sampleIsThere`, через `gaip_sampleReadings`);
- **перечень входов** — `assets/calculation-inputs.schema.json`, запись `"samples.water"` (`:789`): `label: "a water test"`, `filledIn: ["data.water"]`; место `"data.water": "Data -> Water"` (`:957`);
- **фраза панели** — `app/app/Support/AnalysisNotice.php`, `inputNotEnteredText`: «{Module} was not calculated because {label} has not been entered. Add it in {place}.»; имя модуля `'water' => 'water quality'`.

Для воды это даст: «Water quality was not calculated because a water test has not been entered. Add it in Data -> Water.»

## План

1. **`assets/dependency-graph.json`, узел `water-blender`:** `"requires": []` → `"requires": ["samples.water"]`. Больше в устройстве ничего не нужно: вход уже в перечне, ворота, запись «не применимо» и фраза панели общие.
2. **Тест:** `tests/gh-NNN-water-quality-needs-a-water-test.test.js` на `tests/lib/orchestrator-bench.js`, по образцу `tests/gh777-a-table-that-was-not-computed-is-read-as-absent.test.js`.
   - **положительный контроль:** с пробой воды (`?water=<id>`) `computed.water` — строка, её класс солёности следует из пробы;
   - **случай:** без пробы воды (`?water=none`) в `computed` нет ключа `water`. В записи прохода `water` отмечен неприменимым, отсутствующий вход назван `samples.water`. «Low salinity risk» в проходе не появляется;
   - **сквозной:** та же запись даёт через `AnalysisNotice` фразу выше. Если у панели уже есть набор, собирающий фразу из записи прохода, случай добавляется туда;
   - **отрисовка не падает** на случае без пробы — это следствие 3гф, и тест утверждает его здесь тоже.
3. **Пины графа.** `tests/gh777-what-a-node-cannot-run-without.test.js:61–62` утверждают `requires` ткани и MLSN. Требование воды добавляется туда же. Это тест смысла, он и должен меняться.

## Подводные камни

- **3гф обязан быть сдан раньше.** Без проверки типа на `:6988` (`(Me = n).indexOf`) ворота снимут воду, извлечение подставит `{ status: "Not computed" }`, и отрисовка уронит каждый прогон 6 площадок с `calculation-error`. Разработчик прогоняет весь `jest` до правки и печатает перечень покрасневших после. Каждый покрасневший — это либо «утверждал подстановку» (меняется), либо «не должен был зависеть от воды» (называется вслух).

Показания по отдельности — **предложение, требует решения**: это `safeNum(…, 0 | 7)` внутри движка, класс «значения по умолчанию», около 3–5 мест в `waterEngine`.
- **Смежные узлы проверены.**
  - `salinity-penalty-engine` уже требует `water.ecw`;
  - `soil-structure-engine` зовётся с `computed.water` (`cascade-orchestrator.js:893`) и терпит его отсутствие (`soil-structure-engine.js`, `extractWaterChemistry`, `if (waterResult && waterResult.blendedMgL)`);

## РЕШЕНИЕ АНАЛИТИКА 01.10 — по возврату: откуда движок воды читает показатели

Возврат ревьюера: мутация прошла зелёной. Ворота спрашивают, есть ли проба, но не спрашивают, есть ли в ней показатель, и обе подстановки внутри движка остались — `safeNum(e.water.ecw, 0)` и `safeNum(e.water.pH, 7)` (`hub-tissue-v3.js`, `waterEngine`, `:4829–4830`). Вопрос разработчика: из пробы или из состояния.

**Движок читает состояние прохода — и только его.** В пробу он сам не ходит.
1. **Состояние уже собрано из пробы тем же читателем, что спрашивают ворота.** `gaip_build_state`, блок воды (около `:2292`): `gaip_waterFromActiveSample()` (`:1497`) → `gaip_sampleReadings("water")` (`:1464`). Ворота (`hub-orchestrator.js`, `sampleIsThere`, `:1820`) спрашивают ту же `gaip_sampleReadings`. Источник один. Если движок пойдёт в пробу сам, появится второй читатель.
2. **Сценарии передают своё состояние воды.** `runCascade(scenarioState, …)` (`cascade-orchestrator.js:1111`). Движок, читающий пробу, молча игнорировал бы воду сценария.

**Где расходятся «проба несёт показатель» и «состояние не несёт».** Только в первом проходе рамки, до прихода проб (`GH-589`). `gaip_namedSample` отвечает `not-found`, ворота по `GH-777` открываются («ещё не пришло» — не «не введено»), а состояние показаний ещё не имеет. Этот проход заменяется вторым и в строку не пишется (`_cascadeStale`). Сегодня в нём срабатывают подстановки 0 и 7.

**Число разработчика «8 из 13» по базе не воспроизводится.** Строка прогона состояния воды не хранит: у `inputs` ключи `site`, `normals`, `samples`, `sensors`, `weather`. Замер `SELECT` по сохранённым прогонам: пробы воды, названные прогонам, — 326, 115, 54, `Water_3_l5q6` (New test - location, все пять её проб несут pH), — несут и `EC`, и `pH`. Проба без pH одна, 114 на Russley, и ни одному прогону она не названа. Из базы число не проверить, это заявка.

**Что меняется:**
1. **Ворота спрашивают показатель, без которого движку нечего сказать, — через того же читателя пробы, с теми же тремя ответами `GH-777`.** Новое требование в узле `water-blender`: `"requires": ["samples.water", "samples.water.EC"]`. В `inputIsThere` (`hub-orchestrator.js:1795`) ключ вида `samples.<вид>.<показатель>`:
   - `none` → нет;
   - `not-found` → ворота открыты (доставка);
   - иначе → есть ли ключ в `gaip_sampleReadings(<вид>)`.

   Требование по пути состояния (`water.ecw`) не годится: в первом проходе оно записало бы «не введено» то, что ещё не пришло. Это ровно то смешение, которого `GH-777` избегал.
2. **Перечень входов первым:** запись `samples.water.EC` с подписью для панели и местом `data.water`. Панель соберёт её фразой владельца: «Water quality was not calculated because … has not been entered. Add it in Data -> Water.».
3. **Подстановки в движке снимаются обе:**
   - нет `ecw` → движок возвращает `null`, вердикта нет. Это возможно только в первом проходе. Отрисовку держит проверка типа 3гф;
   - нет `pH` → строки, зависящие от pH (около `:4928`, `:4932`, `:4959`), не пишутся. Семёрки нет. pH не требуется: проба воды без pH — это проба воды.
4. **Тест:**
   - проба с `EC` и без `pH` → вода посчитана, pH-строк нет, `7` нигде;
   - проба без `EC` → вода не посчитана, в записи прохода `samples.water.EC`;
   - первый проход с `not-found` → ворота открыты, движок без показаний отдаёт `null`, а не «Low salinity».

   Мутации для ревьюера: вернуть `safeNum(…, 0)` или `safeNum(…, 7)` → красный; снять `samples.water.EC` → красный на пробе без `EC`.

**Что печатается человеку:** сегодня ничего не меняется. У всех проб воды, названных прогонам, есть и `EC`, и `pH`. Меняется для будущей пробы:
- без `EC` — строка панели;
- без `pH` — пропадают pH-советы движка (их видит только `/hub`); статус карточки на Forensic Record может сдвинуться.

Новый текст один — подпись входа в перечне. Подписи входов пишем мы, фраза панели — её, утверждённая.
