## 3дз — площадка на AA без кода сертификата: общая полоса по текстуре, `S277` уходит

**Решение владельца — (а).** Как экран: сервер (`SampleAnalysisController`) судит по `AaRanges::forSoilType(текстура)` и перекрывает сертификатом только при коде.

**Устройство.** В отчёте уже есть цепочка, которая без кода берёт общую полосу: `resolveSufficiencyRanges` (`nutrition-program-inputs.js`) — сертификат, если `deriveCode` его дал, иначе полоса `sands`/`others` с подписью «Ammonium-acetate generic sufficiency band (<texture>)». Вторая цепочка в `collectData` подставляет `S277`. Без кода `data.soil.thresholds` берутся из уже разрешённого `_programInputs.ranges`. Своего литерала и своей ветки выбора нет.

**Места — 3:**
1. `word-export.js`, блок выбора сертификата AA (`if (!aaSampleType) aaSampleType = 'S277'` и запасная ветка «falling back to S277» для неизвестного кода). Без кода — `aaSampleType = null`, пороги из `_programInputs.ranges`, источник `texture-band`. Комментарий GH-482 «The default itself stays… domain question nobody has answered» переписывается на месте: вопрос решён.
2. `word-export.js`, подзаголовок таблицы (`_b35fix441_sampleTypeCode … : 'S277'`, `… : 'TURF Ryegrass, Sand (S277)'`). Без кода печатается подпись общей полосы из `resolveSufficiencyRanges`, а не текст о сертификате и пересчёте из me/100g.
3. `word-export-combined.js`, тот же подзаголовок (`… aaSampleType) || 'S277'`, `… || 'TURF Ryegrass, Sand (S277)'`).

**Что меняется на экране клиента.** У 4 из 8 AA-площадок стенда отчёт судит P, K, Ca, Mg и S по полосе текстуры, как экран. S начинает судиться: у `S277` порога S нет, у общей полосы есть (30–60). Строки pH, Na, CEC, TBS, VW, OM есть только у сертификата. У площадок без кода в отчёте они идут без границы. Что по ним печатает экран — не проверяла, признак 3 печатает.

**Признаки, jest на песочнице выгрузки:**
1. **Следствие:** площадка AA, Creeping Bentgrass, песок (кода нет), проба со значениями 155 (K 85, P 18, S 12, Ca 820, Mg 95). Вердикт отчёта по P, K, Ca, Mg, S равен вердикту по `aa-ranges.json` `bySoilType.sands` — ожидание читается из файла в тесте, не литералом. **Красное до правки:** P «ниже» (граница S277 20), Mg и S — в норме или без границы.
2. **Контроль:** ryegrass на песке (код `S277` выводится) — пороги сертификата, как сегодня.
3. **Печать осмотренного:** по каждой строке — элемент, граница, источник (`certificate` / `texture-band`).

**Границы:**
- **Общая полоса в браузере — литералы `ammonium-acetate-methodology.js`, а не `aa-ranges.json`.** По чтению значения P, K, Ca, Mg, S сегодня равны в обоих файлах для обеих текстур, но это две записи. После 3дз совпадение отчёта с экраном держится на этой копии. Перевести отчёт на одного читателя — предложение, требует решения, в 3дз не входит.
- **Заголовок колонки «Hill Labs AA»** у площадки без кода (`soilThresholdLabel`) — имя третьей стороны у полосы Gilba. Это переименование R8.

**Соотношение с R8.** Ответ (а) — это вариант «убрать» вопроса В3. **В3 снимается.** Из R8 уходят 3 места подстановки `S277` — они здесь. В4 и В5 (чьими словами пишется происхождение, участвует ли порог без происхождения в расчёте) остаются: они решают, как печатаются строки общей полосы.

## 3ди — гипс по SAR: страница по порогу своей травы, как отчёт

**Сегодня.** Отчёт: одна оценка воды, `WATER_SET_2` (C3: SAR warning 4 / critical 6; C4: 6 / 9), тип травы — `_speciesBasis(turf)`, уровень — `_waterLevel`, строгое `>`. Страница и движок воды судят по 3 / 6 / 9 (иногда 18) для всех трав, нестрогим `>=`. Тип травы не знают ни страница, ни движок (`grep` по `isC4`, `useC3Targets`, `overseedDominant`, `species` — нет).

**Устройство.**
- Набор 2, выбор типа травы и шкала уровня выносятся из `word-export.js` в один общий модуль. Образец — `k-reconciliation-decision.js` (`GH-292`). Его зовут отчёт и движок воды. Одна запись, своих порогов ни у кого нет.
- Движок воды на прогонщике считает уровень SAR по этому модулю с типом травы площадки и сохраняет уровень в диагностиках.
- Страница печатает сохранённый уровень. Сохранённых диагностик нет — показывает «не оценено», а не считает по своим порогам.

**Места — 9:**
1. новый общий модуль (`WATER_SET_2`, `_speciesBasis`, `_waterLevel` — перенос, значения не меняются);
2. `word-export.js` зовёт модуль вместо своих определений;
3. движок воды: `getSARStatus` и его вызовы (`water-progressive-disclosure-WITH-SOIL-INTERACTION.js`) — уровень по модулю, тип травы из состояния прогонщика (**не проверено**, есть ли у прогонщика в этом месте `turf`; если нет — его дают те же входы, что отчёту);
4. `water-balance-analysis.js`, состояние воды (`sar >= 9 … sar >= 3`, и от него определения со словом gypsum);
5. там же, карточка риска структуры почвы (`effSar >= 18 / 9 / 3` → `gypsumNeeded`);
6. там же, строка SAR, запасная ветка (`wb.SAR >= 9 / 6 / 3`);
7. там же, рекомендации (`wb.SAR >= 9 / 3`);
8. там же, текст подсказки шкалы SAR («9–18 — High — gypsum likely needed»): шкала зависит от травы, неизменный текст становится неверным;
9. списки скриптов видов: модуль грузится на Analysis, прогонщиком и выгрузкой.

**Что меняется на экране клиента.** В полосах SAR 3–4 (C3) и 3–6 (C4) страница перестаёт советовать гипс, как отчёт. Выше границы уровень и его слово совпадают с отчётом.

**Признаки:**
1. **Следствие:** проба воды SAR 3.5 на C3 и SAR 5 на C4. Совет гипса на странице и в отчёте — «нет» в обоих. SAR 4.5 на C3 — «да» в обоих. Ожидание — из модуля (объявление), не литерал. **Красное до правки:** страница советует при 3.5 и 5.
2. **Контроль:** SAR 10 — «да» у обоих и до, и после.
3. **Печать осмотренного:** проба, тип травы, уровень страницы, уровень отчёта.

**Границы:**
- **Сохранённые диагностики старых анализов меняются только после нового прогона**, как у `GH-820`.
- **Карточка структуры почвы судит по `max(SAR, SARadj)`, отчёт — по SAR.** Это расхождение того же рода по показателю, а не по порогу, и в 3ди не входит. На скольких пробах `SARadj > SAR` — не мерила.
- **Гипс по натрию почвы** (`soilNa >= 30 / 60 / 100`, pH + Na) — другой повод. У отчёта на него свои условия, решение агронома («which of those thresholds is right»). В 3ди не входит.

## Остатки `GH-821`

Ни один не делает 3дз или 3ди неполными. Читатели pH и третье определение «pH есть» не касаются ни выбора полосы AA, ни уровня SAR.
