## v11.20.18 (b35fix388)

**Cotula bowling-green state writes routed through the hub-store proxy.** Same bug class as b35fix386 (closed for the `.soil` slot in `nutrition-calendar.js syncSoilFromDOM`), now closed for the `.turf` slot in `cotula-bowling-green.js handleBowlsSelection`. Pre-fix code at lines 546-552 wrote 6 keys via direct property assignment to `window.GAIP_STATE.turf.<key>`. Under the hub-store proxy installed in `gilba-hub-v2.js` (~line 1393), those writes silently drop: the getter synthesises a fresh object from `c.peek('inputs.turf')` on every read, mutations land on the ephemeral synthesised object and are GC'd. Only the setter's `e.inputs` and `e.turf` branches route writes into the store.

**Production impact.** Cotula mode was silently failing for any client running bowls turf since the proxy was installed (build origin unknown — predates b35fix386). Four downstream readers — `turf-profile-controller.js:836` (cotula species guard), `nutrition-uk-fertiliser-integration.js:690` (bowling-greens surface mapping), `hub-tissue-v3.js:1102` (DOM-vs-state species resolution), `site-config-persistence.js:406` (bowls profile restore) — all read `window.GAIP_STATE.turf.cotula === true` and saw `undefined`. The mode preset never stuck through the state layer; downstream nutrition and tissue logic fell back to the default species. Latent in production telemetry because cotula sites do not fire the visible asymmetric-export pattern Rockingham GC did with the soilSeenK=0 bug — failure mode here is "wrong species selected silently," not "obviously wrong K value in summary table."

**Diagnosis evidence (sandbox simulation, 2026-04-29):**

- Read of the actual proxy install at `gilba-hub-v2.js:1393-1422` confirmed `e.turf` setter branch at line 1415: `c.set('inputs.turf', e.turf, 'legacy-state-write')` — replaces wholesale, does not patch
- Simulated proxy round-trip with the production getter shape (`turf: c.peek('inputs.turf')` synthesised per-read, defensive shallow clone) reproduced the silent drop on the pre-fix pattern: `if (!turf) turf = {}; turf.X = 'bowls'` → readback returns `undefined` for `.X` while the seeded `variety` key persists
- Same simulation confirmed the post-fix routed write with `Object.assign({}, existingTurf, {...cotulaKeys})` lands all 6 keys AND preserves `variety` and `companionSpecies` from prior TurfProfile state

**Fix in `assets/cotula-bowling-green.js`:**

Replaced the 7-line direct-write block with a routed write that reads existing turf state, merges, and assigns through the setter contract:

```js
var existingTurf = (window.GAIP_STATE.inputs && window.GAIP_STATE.inputs.turf)
    || window.GAIP_STATE.turf
    || {};
window.GAIP_STATE = {
    inputs: {
        turf: Object.assign({}, existingTurf, {
            turfType: 'bowls',
            surfaceType: 'cotula_bowling_green',
            speciesKey: 'cotula',
            grassSpecies: 'cotula',
            physiology: 'dicot',
            cotula: true
        })
    }
};
```

The `Object.assign({}, existingTurf, {...})` merge is essential because the setter's `e.inputs.turf` branch replaces the slot wholesale — without the merge, every bowls activation would wipe `variety`, `companionSpecies`, and any other turf state TurfProfileController populated. Mirrors b35fix386's pattern but adds the merge step (b35fix386's `soilState` was a complete locally-built object, not a partial override). Wrapped in `try/catch` with a `[CotulaBowling b35fix388]` warn — same defensive shape as b35fix386.

The outer `if (window.GAIP_STATE)` guard from pre-fix stays — protects against scripts loading before the proxy installs (early init race). The defensive `if (!window.GAIP_STATE.turf) window.GAIP_STATE.turf = {}` line is removed; the routed write creates `inputs.turf` on first activation if needed.

Behaviour downstream of the write — the `tpc.selectTurfType('bowls')` call, the `gaip:turf-profile-change` event dispatch, the AA methodology force, the species select population — all unchanged.

**Files changed:**

- `tests/cotula-bowling-green-b35fix388-proxy-write.test.js` — new. 17 assertions across two suites: source-pattern checks (correct setter contract, all 6 keys present, legacy direct writes gone, merge-with-existing pattern, try/catch wrapper, behaviour-unrelated lines preserved) and simulated proxy round-trip (all 6 keys land, each of the 4 downstream readers sees the cotula flag, idempotency on re-fire, pre-existing turf state preserved, pre-fix pattern silently drops under the same proxy as a frame-pinning regression check).

## v11.20.16 (b35fix386)

**Live-preview soilSeenK=0 root cause fixed.** The b35fix378–b35fix385 chain treated this as a writer-asymmetry problem inside `syncSoilFromDOM`. b35fix385's diagnostic plus four DevTools console probes against production state revealed the actual cause: **`window.GAIP_STATE` is a getter/setter pair installed by the hub-store, not a plain data property**. The getter synthesises a fresh object on every read from `c.peek('inputs')`, `c.peek('computed')`, `c.peek('inputs.turf')`, etc.; assignments to top-level `.soil` land on that ephemeral object and are GC'd. Only the setter's `e.inputs` branch routes writes through `c.transaction((t) => t.set('inputs.<key>', val, 'legacy-state-write'))`. The pre-fix `window.GAIP_STATE.soil = soilState` writeback at the end of `syncSoilFromDOM` had been silently no-opping for some unknown number of builds.

**Diagnosis evidence (DevTools console, 2026-04-29):**

- `Object.getOwnPropertyDescriptor(window, 'GAIP_STATE')` → `{enumerable: false, configurable: true, get: ƒ, set: ƒ}` — confirms proxy
- direct `window.GAIP_STATE.soil = { ppm: { K: 999 } }` from console → `window.GAIP_STATE.soil` reads back `undefined` afterwards — confirms drop
- `window.GAIP_STATE = { inputs: { soil: { ppm: { K: 999 } } } }` → `window.GAIP_STATE.inputs.soil` reads back `{ppm:{K:999}, K:999}` — confirms setter route works
- `_gilbaAnalysisRunCount` unchanged across the routed write — no analysis-cascade re-trigger; safe to call from inside `generate()`

**Why b35fix382's identical-across-runs `soilSeenK=0` evidence pointed here:** every site, every sample, every click landed at K=0 because the synthesised state never had a top-level `.soil` key, so `extractPpm({}, 'K')` returned 0 via the `parseFloat(undef.ppm) || 0` fallback. Word export survived because it constructs `perSampleInputs.soilPpm` as a plain local object handed straight to `computeProgram(perSampleInputs)` — never round-trips through the proxy.

**Why b35fix380's elemental K correction (44 → 38.67) hid the symptom from end users on K-sufficient sites:** at the inflated annual K demand of ~108 kg/ha (live preview), the recommender's scoring with the corrected K density still put nitrate-K specialty products below cheaper composite alternatives. So the live preview's wrong K demand never produced a wrong product selection on Rockingham GC's K-sufficient soils. The bug was real but agronomically silent post-b35fix380 on that specific client. On K-elevated sites with paspalum or warm-season turf (e.g. GTS), the nitrate selection is demand-driven and worked correctly through the export path; only the live-preview annualK number was wrong.

**Fix in `assets/nutrition-calendar.js`:**

1. **Writeback** (end of `syncSoilFromDOM`) — replaced `window.GAIP_STATE.soil = soilState` with `window.GAIP_STATE = { inputs: { soil: soilState } }`. The setter accepts the write and routes it via the `e.inputs` transaction branch into `inputs.soil` in the actual store.
2. **Carry-over read** (top of `syncSoilFromDOM`) — replaced `var existing = window.GAIP_STATE.soil` with `var existing = (window.GAIP_STATE.inputs && window.GAIP_STATE.inputs.soil) || window.GAIP_STATE.soil`. Same root cause: the legacy read was always undefined on the synthesised view.
3. **Read in `collectFromState`** — replaced `const soil = state.soil || {}` with `const soil = (state.inputs && state.inputs.soil) || state.soil || {}`. The legacy `state.soil` fallback is preserved in case any other call site populates the legacy slot directly (none currently do, but it costs nothing).
4. **`surfaceType` resolution** — replaced `state.soil?.surfaceType` with `soil.surfaceType` (using the locally-resolved const that already prefers `inputs.soil`). Without this, `surfaceType` would still fall through to `state.turf?.subCategory || 'sports'` ignoring the user's actual selection.

**Removed**: b35fix385's diagnostic instrumentation (16-checkpoint `_b35fix385_dbg` object, paired captures inside the SM block and DOM scan, single emit at end). It served its purpose and is no longer needed.

**Test:** new `tests/syncSoilFromDOM-b35fix386-writeback.test.js` (10 assertions) pins the exact writeback pattern, the absence of the legacy form, both reads, the surfaceType local-const usage, the try/catch wrap with warn, removal of b35fix385 dbg, preservation of b35fix383 SM-priority block and b35fix384 DOM zero-rejection guard. Stale `syncSoilFromDOM-b35fix385-diagnostic.test.js` removed.

**Smoke verification (sandbox, simulated hub-store proxy):**

- Production scenario (SM has K=141 on `14th_green`, DOM K input empty): `inputs.soil.ppm.K === 141` after writeback; `collectFromState` reads it back as `soilPpm.K === 141, P === 39, Ca === 517` — matches the expected combined-export per-sample values
- Carry-over scenario (second sync call without SM): `ppm.K === 141` preserved from prior write — confirms the carry-over branch reads the store correctly through the proxy

**Production verification target:** next session log should show the live-preview path's K target matching the combined-export per-sample value for the same site/sample (e.g. K=52 removal-only on K-sufficient soils, or whatever the demand-driven number is on K-elevated sites). The Rockingham vs GTS divergence collapses: both clients should show consistent K targets between live preview and Word export.

**Same proxy bug class affects three other modules — flagged in backlog, not in scope for b35fix386:**

- `cotula-bowling-green.js:546-552` — 7 writes to `window.GAIP_STATE.turf.*` (turfType, surfaceType, speciesKey, grassSpecies, physiology, cotula flag). 4 reads of `.turf.cotula` exist downstream — live bug, cotula bowling-green mode setting is silently failing

**Backlog also adds**: nitrate-K source selection should be species/water-driven, not pure-demand-driven. Current recommender picks nitrate K when K demand is elevated AND in a warm temperature window. The case for moving to species-driven (always prefer nitrate over chloride-K on paspalum, fine-leaf bermuda on saline water, etc.) hinges on chloride-avoidance for salt-stressed rootzones, not on K demand. Design extension: gate the K-source selector on `(species ∈ chloride-sensitive-set) OR (water.Cl > threshold) OR (water.EC > threshold)`, mirroring how Mulder's interaction checker already reads water chemistry. Citations: Duncan & Carrow 2000, Lee et al. 2005 paspalum NRT2 nitrate preference. Touches `au-fertiliser-products.js selectPotassiumSource` (or its successor — selectPotassiumSource was deleted in b35fix330; the live recommender path for nitrate K source is whatever replaced it). Separate build, separate verification.
